# Skills in Praxis

A skill is a reusable procedure. Praxis finds relevant names and descriptions from the current question, opens a selected procedure when needed, and uses the tools and permissions already configured in Chat. Skills are separate from facts and preferences, and importing one does not connect a service or grant access.

- Open **Skills** to read, copy, enable or disable a starter skill. In a tool-enabled conversation, ask “Use `$source-verification` to reconcile these two sources,” or ask normally and let Praxis find a match.
- To teach a procedure, use a **local model with tool support**, turn Tools on in Chat, and allow proposals in Privacy. Give Praxis a concrete walkthrough or a successful run and ask it to draft a skill. In **Skills → Awaiting review**, check the exact text and approve or reject it. Approval is required even when Chat can edit other records.
- To bring an existing skill, paste its `SKILL.md` in **Skills → Import Markdown**. Review it before use. Copy an existing version as `SKILL.md` to export it. This implements the text-only subset of the [Agent Skills format](https://agentskills.io/specification); scripts, reference files and assets are not imported or executed. Optional metadata such as `allowed-tools` has no effect on Praxis permissions.
- To revise a skill, ask a local chat to open its current version and propose a change, or import revised Markdown under the same name. Review the old and new versions side by side. A stale approval cannot replace a newer version. Bundled skills are maintained with the app; to customize one, copy it under a fresh name. Disable a skill to prevent it from loading on later turns.

Learned and imported skills are stored in the local catalog and are not offered to remote or CLI models. Private drafts are visible in the desktop app, not to the agent. Approved versions are paired with a SHA-256 digest and retained for inspection. The starter library is shipped with the app; several workflows rely on source files or existing integrations the owner supplies. A playbook for GitHub, native reverse engineering, design, spreadsheets, or deployment does not install those integrations.

Version one covers text review, metadata discovery, on-demand execution guidance, and a transferable starter library. Sandbox execution of skill packages, narrated screen capture training, automated quality scoring/deprecation, and remote disclosure of private skills are outside this implementation. See [#298](https://github.com/berniemackie97/Praxis/issues/298) for the broader roadmap.
