# ADR 0042: Authorized opaque synchronization and optional private TLS host

**Status:** implementation under review in #19. Transactional opaque store merged in PR #271; separately enabled private TLS host and client AES-GCM codec are proposed in the current #19 PR. This is not production-host approval.

## Decision

D0 SwiftUI and the .NET worker continue using private inherited pipes; Praxis.Api remains health-only. Future optional D1/D2 private synchronization uses its own executable and opt-in TLS listener (ADR 0041). The remote collection identifier is a **synchronization security space**, not a many-to-many organizational collection (ADR 0003). The implemented transport accepts only **client-held encrypted spaces**; it cannot silently upload local-only data, downgrade encryption or begin trusted-host plaintext processing.

INoteSyncExchange contains decrypted offline-journal note projections and is never an HTTP wire DTO. The remote version-1 messages contain only permitted opaque encrypted bytes, device/space/epoch/operation identities, revisions, tombstones and ordered cursors. The client-side AES-256-GCM note codec authenticates path and Markdown under associated data binding space ID, log epoch, record ID, resulting revision, upsert/restore action and content-key epoch. Enrolled devices must independently decrypt and enforce hidden path/link constraints; a ciphertext host cannot inspect or prove them, nor verify an authorized malicious client truly encrypted its payload.

A Kestrel TLS 1.3 handshake requires an actual client certificate chained to an operator-pinned CA. The certificate is read only from the verified connection, never request headers. A signed one-use device challenge binds security space and exact read/write operation. Current enrollment approval, membership/grants, key-epoch and pending rekey must be checked again under the registry's synchronous revocation fence while the protected data transaction executes. The host keeps no issuer private key. CA CRL/OCSP publication, host key custody and compromise response are unimplemented operational gates (#65/#15), distinct from registry device revocation.

Every accepted mutation atomically commits its record revision, event, idempotency receipt and sequence in the separate SQLite WAL/FULL sync store. Retries with the same device/operation ID and bytes return the original receipt; altered replays or stale revisions fail without plaintext conflict data. Pull cursors are exclusive, pages bounded 1–100 and high-water marks transaction-consistent. Tombstones carry no old ciphertext mislabeled with the new revision. Old-key records/events after a rotation cause ResetRequired rather than silent disclosure. There is no complete snapshot/re-encryption/rebootstrap or compaction floor yet.

The private host limits payload bytes, connections, in-flight work, request timeout and per-certificate request rate. These are protective hard ceilings, not measured capacity promises. A request cancelled after commit may have no observed acknowledgment; the device must retry the exact already-durable mutation with a new proof. Identity registry, sync database and separately held keys are not a globally atomic multi-database backup. Safe diagnostics, storage, retention, rollback, operator CA and physical test obligations remain #65/#46/#47.

**Explicit noncompletion:** the #19 host is not a certified D1 service, and #18 journal-to-ciphertext integration, #20 encrypted attachment integrity/atomic reference changes, lost-device/key rotation rebootstrap, real cross-device interrupted transport, and host security/load tests remain open. Do not close #19 or parent #56 until evidence satisfies those requirements. See the [operator guide](../operations/private-sync-host.md), ADR 0006, ADR 0038 and ADR 0041.
